# Mes tours — consignes pour Claude

- **Tests ciblés** : après une modification, lance seulement les tests qui la concernent, avec `npm run test:cibles` (skill `/tests-cibles`), et `npm run typecheck` si du TypeScript a changé. Ni la suite entière, ni le build, ni `npm run test:e2e` (les tests dans Chrome, quatre à cinq minutes) : la CI GitHub Actions les joue sur la pull request, et sa correction automatique ramène ici ce qui échoue.
- **Versions** : chaque changement s'écrit dans `CHANGELOG.md`, sous « Non publié », dans le même commit que lui (`npm run check:changelog` contrôle la forme). Avant la fusion, la pull request porte son numéro de version, dans un commit « Version X.Y.Z : … » qui renomme « Non publié » en `## [X.Y.Z] — AAAA-MM-JJ` avec sa ligne « N commits » (N = commits de `main` + ceux de la branche, ce commit compris), ajoute la ligne du tableau en tête et le lien `[X.Y.Z]: …/releases/tag/vX.Y.Z` en bas, et met `src/version.ts` au même numéro ([semver](https://semver.org/lang/fr/) : correctif, mineur ou majeur selon les changements). Ne jamais fusionner une PR encore sous « Non publié ».
